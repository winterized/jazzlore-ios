# Architecture

How the system is built today. Any change that makes this file wrong updates it in the same branch. Keep it to what a new session cannot see quickly in the code: the parts, where their boundaries are, how data moves between them, and why it is built this way.

First written 2026-10-09 from the code, the README and the notes of earlier sessions. Statements marked *(inferred)* were not confirmed against a running app.

## Overview

Four iOS apps, each a thin Capacitor 8 shell around one of the Jazzlore PWAs (Metronome, Chords, Scales, Musicians). The PWA's production build is bundled into the app and served from `capacitor://localhost`, so each app runs fully offline and looks exactly like the installed web app. There is no native UI apart from the Musicians home-screen widget. The PWAs themselves are built in the separate web repository, winterized/jazzlore; nothing here changes how they behave.

## Components

- **One Capacitor project per app**, in `metronome/`, `chords/`, `scales/` and `musicians/`. Each has its own `package.json`, `capacitor.config.ts` (app id `com.jazzlore.<app>`, `webDir: www`) and a committed `ios/` tree:
  - `ios/App/App.xcodeproj`: target `App`, product name "Jazzlore <App>", home-screen name "Jazz <App>" (`CFBundleDisplayName` in `Info.plist`). There are no shared schemes, so Xcode autocreates one called `App`; Musicians also has a shared `MusicianWidgetTests` scheme.
  - `ios/App/CapApp-SPM`: a local Swift package, written by the Capacitor CLI, that pulls `capacitor-swift-pm` (pinned in `Package.resolved`) and the Capacitor plugins from `<app>/node_modules/@capacitor/*`. Xcode cannot resolve packages until `npm ci` has run in the app.
  - `AppDelegate.swift` is the Capacitor default; URL opens go to `ApplicationDelegateProxy`.
  - Plugins: `@capacitor/splash-screen` in all four; Musicians adds `@capacitor/app` (deep links) and `@capacitor/share`.
- **Musicians widget** (`musicians/ios/App/MusicianWidget/`), a SwiftUI WidgetKit extension embedded in the Musicians app ("musician of the day", `.systemSmall`):
  - Content is bundled at build time: `Resources/musicians.json` (39 records of `{id, name, fact}`) and `Resources/Portraits.xcassets` (one imageset per record, named by `WidgetMusician.assetName`).
  - `MusicianRotation` picks `daysSinceEpoch % poolSize`: deterministic, offline, the whole pool before any repeat. `Provider` schedules one midnight entry per day for 30 days with policy `.atEnd`. No network, no stored state.
  - A tap opens `jazzlore-musicians://musician/<id>`. The scheme is registered in the app's `Info.plist`; `@capacitor/app` hands it to the web app, which maps it to a route.
  - `MusicianWidgetTests` is a hostless XCTest bundle that compiles `Model.swift` directly. It is the only automated test in the repository.
- **Root tooling**:
  - `Makefile`: `make <app>` builds the PWA in the web repository (`pnpm -F @jazzlore/<app> build`), copies its `dist/` to `<app>/www/` and runs `npx cap sync ios`.
  - `scripts/generate-icon-layers.mjs` (`npm run icons:layers`): turns `<app>/assets/icon-layers/*.svg` into PNG layers for Icon Composer.
  - `scripts/generate-splash-masters.mjs` (`npm run splash:masters`): writes `<app>/assets/splash-master.png` (app mark plus a "jazzlore" wordmark rendered from the vendored Geist font).
  - `scripts/test.sh`: builds all four apps for the simulator and runs the widget tests.
- **App icons**: each app ships an Icon Composer `AppIcon.icon` (iOS 26 Liquid Glass), wired into `project.pbxproj` like an asset catalog. The older flat `AppIcon.appiconset` is kept as the rollback.
- **Launch screen**: `LaunchScreen.storyboard` shows the `Splash` imageset on `#0a0a0a`. The plugin keeps the splash up until the web app calls `SplashScreen.hide()` after it mounts, with a minimum visible time. That code is in the web repository.

## Data and state

- `<app>/www/`, `ios/App/App/public/`, `capacitor.config.json` and `config.xml` are generated by `make <app>` and `cap sync`, and are git-ignored. `scripts/test.sh` writes a placeholder web bundle when they are missing, so a build here proves the native side compiles, not that the web bundle is right.
- The widget pool and portraits are produced in the web repository by `pnpm widget:content` and copied in by hand. `make musicians` does not refresh them.
- Committed design sources: `<app>/assets/` (icon layers, `icon-only.png`, splash master, App Store screenshots and text).

## External services

- **Musicians BFF**: a Cloudflare Worker at `musicians.jazzlore.com`, part of the web repository. From `capacitor://localhost` it is cross-origin and sends no CORS headers, so Musicians enables `CapacitorHttp` in `capacitor.config.ts` and the web app calls the absolute BFF origin when it runs natively. The other three apps make no network calls *(inferred)*.
- **winterized/jazzlore** (public): the web monorepo with the PWAs, the BFF and the widget content generator.
- **winterized/JazzDBPopulator** (private): the Neo4j graph of musicians and records behind the BFF. Data defects, such as missing or duplicate nodes or untitled records, are fixed there.
- **App Store Connect**: archives are made by hand in Xcode (Product → Archive). There is no CI and no Xcode Cloud.

## Constraints

- iOS 16.0 deployment target. The PWAs' CSS uses `:has()`, container queries and `color-mix()`.
- Swift Package Manager only; there is no CocoaPods.
- No entitlements or native capabilities beyond the widget extension and the URL scheme.
- Metronome, Chords and Scales declare `ITSAppUsesNonExemptEncryption = false`; Musicians' `Info.plist` does not.
- The PWA's service worker does not register on the `capacitor://` scheme; offline comes from the bundled files *(inferred)*.
