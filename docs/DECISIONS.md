# Decision log

Dated decisions, newest last. Entries are only ever added: to reverse a decision, add a new entry that names the one it replaces.

Each entry has this shape:

    ## YYYY-MM-DD: short title
    Decision: what was decided.
    Why: the reason, and what was rejected.
    Source: docs/briefs/<file>.md, or "implementation choice" with the task's slug.

The entries up to 2026-06-09 were reconstructed on 2026-10-09 from the git history and the notes of earlier sessions, which no session reads any more. Their source says so.

## 2026-05-29: Capacitor 8 shells with Swift Package Manager
Decision: Each PWA ships as a thin Capacitor 8 shell, one self-contained project per app directory. Its iOS platform uses Swift Package Manager, Capacitor 8's default.
Why: Wrapping the existing PWAs needs no change to the web code. CocoaPods was not installed and is being deprecated, and with almost no plugins SPM carries little risk.
Source: notes of earlier sessions (auto memory, capacitor-ios-pattern).

## 2026-05-29: iOS 16 deployment target
Decision: Every app and `CapApp-SPM` target iOS 16.0, not 15.
Why: The PWAs' Tailwind v4 CSS uses `:has()`, container queries and `color-mix()`, which all need iOS 16.
Source: notes of earlier sessions (auto memory, capacitor-ios-pattern).

## 2026-05-29: Web build bundled, offline, never committed
Decision: The PWA's production build is bundled in the app and served from `capacitor://localhost`; the app never loads a live URL. `www/` and `ios/App/App/public/` are generated by `make <app>` and git-ignored.
Why: It gives exactly the installed-PWA experience, offline, with no changes to the web repository; the PWAs' absolute asset paths work as they are.
Source: notes of earlier sessions (auto memory, capacitor-ios-pattern); README.

## 2026-05-29: Signing team committed, signing material ignored
Decision: `DEVELOPMENT_TEAM = V78LBF2887` with automatic signing is committed in each `project.pbxproj`. Keys, certificates and provisioning profiles are git-ignored.
Why: A Team ID is public metadata, not a secret. This reverses an earlier instruction not to commit Team IDs.
Source: notes of earlier sessions (auto memory, capacitor-ios-pattern).

## 2026-05-29: Product and display names, export compliance
Decision: `PRODUCT_NAME` is "Jazzlore <App>"; the home-screen name (`CFBundleDisplayName`) is "Jazz <App>"; the App Store name is set in App Store Connect. Metronome, Chords and Scales declare `ITSAppUsesNonExemptEncryption = false`.
Why: The apps are offline and use only exempt encryption, so no compliance prompt appears on each upload.
Source: notes of earlier sessions (auto memory, capacitor-ios-pattern).

## 2026-05-30: iOS 26 Liquid Glass app icons
Decision: Each app's icon is an Icon Composer `AppIcon.icon` built from three layers (background, accents, dot). The same recipe applies to all three apps: the dot group has Liquid Glass on and translucency off, accents are matte, and the background has an automatic fill. The flat `AppIcon.appiconset` stays in git as the rollback; reverting one app's icon commit restores it. Chords is the reference the others are matched to.
Why: A coherent icon family on iOS 26. Opaque glass on the dot keeps the specular highlight while hiding the lines behind it. Icon Composer is the only reliable writer of `icon.json`.
Source: notes of earlier sessions (auto memory, ios26-liquid-glass-icons); docs/ios26-liquid-glass-icons-design.md; PR #1.

## 2026-05-30: Branded splash, dark only
Decision:
- The splash is the app mark (35% width, optical centre at 42%) above a lowercase "jazzlore" wordmark in Geist SemiBold, amber `#f4a233`, baseline at 85%, on `#0a0a0a`.
- It is dark only and designed for portrait. iPhone landscape crops the wordmark, which is accepted.
- `launchAutoHide` is false: the web app hides the splash after mount, with a minimum visible time (800 ms) set in the web repository.
- Splash images are generated from an isolated `--assetPath`, because `@capacitor/assets` would otherwise regenerate the app icon too.
Why: One family look, where only the icon differs. With `launchAutoHide` false, `launchShowDuration` has no effect, and a fixed auto-hide could show an unpainted view on a slow cold launch.
Source: notes of earlier sessions (auto memory, splash-screen-pipeline); PR #2.

## 2026-06-03: Musicians reaches its backend through CapacitorHttp
Decision: Musicians enables `CapacitorHttp`, and its web app calls the absolute BFF origin when it runs natively.
Why: From `capacitor://localhost` the BFF is cross-origin and sends no CORS headers, so a WebView fetch would be blocked. The other three apps have no backend and need neither.
Source: commit b29ce52 (PR #5); README.

## 2026-06-07: Musicians "musician of the day" widget
Decision:
- A self-contained SwiftUI widget with a 39-musician pool bundled at build time (`musicians.json` of `{id, name, fact}` plus `Portraits.xcassets`).
- The pick is deterministic: sequential `daysSinceEpoch % poolSize`, not `hashValue`, which changes between launches. The timeline is 30 midnight entries ahead, with no network and no state.
- A tap opens `jazzlore-musicians://musician/<id>`, and the web app owns the route mapping.
- The content is regenerated by hand in the web repository (`pnpm widget:content`), not by `make musicians`.
Why: It works offline, repeats nothing within a cycle, and needs no backend. The pool can reach sparse "polished" musicians, so any surface that samples beyond the 12 curated greats must expect thin or contract-breaking data (jazzlore#159, JazzDBPopulator#9).
Source: docs/widget-design.md; PR #8; notes of earlier sessions (auto memory, musicians-widget-v1.1).

## 2026-10-09: Task workflow and test command
Decision:
- Work runs as tasks under `CLAUDE.md` and reaches `main` only through `.claude/hooks/land.sh`.
- `scripts/test.sh` builds all four apps for the simulator, without signing and against a placeholder web bundle when the real one is missing, and runs `MusicianWidgetTests`. Each checkout gets its own derived data and its own simulator.
Why: An unattended session needs one command that proves the native side compiles and the tests pass. It must not depend on the web repository's state, and it must work in parallel worktrees.
Source: implementation choice, repository setup.

## 2026-10-09: Review policy for tasks
Decision:
- A task gets at most two reviews.
- Nothing lands while a blocker or major finding is open or disputed. Only the owner can override that, by hand.
- Every finding that was not fixed is listed in the session's final message, minor ones included.
- Review reports are kept in `.claude/reviews/` in the main checkout, git-ignored, and deleted after 30 days.
Why: Runs are unattended, so the check before a merge must not depend on the implementing session's own account of its work, and an unresolved finding has to reach the owner.
Source: docs/briefs/2026-10-09-record-review-policy.md.

## 2026-10-09: Default web repository for make
Decision:
- `make <app>` builds from `$(HOME)/Developer/jazzlore` when `JAZZLORE_WEB` is not set.
- The override keeps its name, `JAZZLORE_WEB`, on the command line or in the environment.
Why: The old default, `~/Documents/jazzlore`, is synced by iCloud Drive, which copied conflict files such as `config 2.xml` into the web build and from there into this repository. Repositories now live in `~/Developer`, outside iCloud. Keeping the variable's name keeps existing commands working.
Source: docs/briefs/2026-10-09-makefile-web-repo-default.md.

Decision:
